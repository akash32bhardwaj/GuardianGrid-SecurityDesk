
## 6. Two behaviour changes to be aware of

Neither is a bug; both change what the system does, and you should know
before a client notices.

**Residents stored as `RESIDENT` now auto-admit.** The gate used to trust
only `KNOWN` and `VISITOR`, so a resident whose registry row said
`RESIDENT` was held at the barrier for a manual guard decision while the
PDF report counted them as verified traffic. `RESIDENT` now folds into
`KNOWN`. That is the fix, but it does widen what passes without a guard
tap.

**`APPROVED` counts as verified but does NOT auto-admit.** Whether a
pre-approved visitor should lift the barrier with no human in the loop is
a society policy call. Adding `"APPROVED"` to `AUTO_ADMIT_ACCESS` in
`api_server.py` is the whole change if you want it. The verified-traffic
figure moves from 71% to 79% on the demo mix, and the dashboard and the
PDF now produce the same number for the first time.

## 7. If something goes wrong

Every changed file has a `.bak` sibling from earlier tonight, and the
deploy script resets to `origin/mediamtx-hls-integration`, so a rollback
is a `git revert` plus a redeploy.

The one thing that is **not** reversible by redeploying is
`db.py --migrate`, which rewrites stored timestamps. It leaves
unparseable rows untouched and is idempotent, but take a copy of
`/data/guardiangrid.db` before running it if you want a way back.

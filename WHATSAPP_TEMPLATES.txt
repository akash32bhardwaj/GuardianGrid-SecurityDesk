The four approved ones were created 1 Oct and confirmed on 16 Oct:
"WhatsApp approval status: Approved", category Utility, and channel
eligibility includes WhatsApp BUSINESS INITIATED — which is the mode that
matters. User-initiated only works inside the 24-hour window the sandbox
already gives you.

A Content SID is HX + 32 hex = 34 characters. The code checks the SHAPE
and falls back to freeform if it fails (OCT-120), so a mistyped SID
produces a silent freeform send, not an error.


WHERE EACH IS READ, AND THE VARIABLE ORDER
------------------------------------------
Variable order is not negotiable: it is the order the caller passes.
Changing the template without changing the caller breaks the send.

1. WA_TPL_SOS          whatsapp_alerts.WA_TEMPLATES["sos"]
   Resident presses SOS -> security head + committee.

2. WA_TPL_ESCALATION   whatsapp_alerts.WA_TEMPLATES["escalation"]
   An incident not acknowledged inside the window.

3. WA_TPL_BRIEF        whatsapp_alerts.WA_TEMPLATES["brief"]
   Morning brief, 7:35 am, to the committee's nominated number.

4. WA_TPL_VISITOR      visitor_notify.py — its OWN credential path, not
   whatsapp_alerts. Somebody is standing at the gate. OCT-128/OCT-129.

5. WA_TPL_CONTRACTOR   whatsapp_alerts.WA_TEMPLATES["contractor"]
   contractors.py _notify_whatsapp(), added 7 Oct.
   send_alert(to, "contractor", [who, direction, gate, when], body)
       {{1}} who (name, or "name (company)")
       {{2}} IN or OUT
       {{3}} gate
       {{4}} time

6. WA_TPL_MONITOR      site_heartbeat.py — runs on the HOST under cron,
   reads cfg["wa_tpl_monitor"] OR the env var. Not in a container.
   variables=[tag, name, detail, time]
       {{1}} tag, INCLUDING its emoji (the code sends "🔴 BLIND" /
             "🟢 RESTORED") — the template must NOT add its own
       {{2}} site name
       {{3}} what happened
       {{4}} time
   This is the most important one. It alerts the founder, who has no
   reason to have messaged the business, and it only transmits when a
   site is ALREADY DOWN. Without the template, the one message you
   cannot afford to lose is the one that fails — into a cron log.


CATEGORY AND OPT-IN (unchanged, still true)
-------------------------------------------
Every template is UTILITY, never MARKETING: each is a response to
something that happened at that person's own gate.

Opt-in: staff numbers are given to us by the society in writing when it
signs. Meta's form asks how people consented — say that.

Business: S&N GuardianGrid Technologies. Sender display name shows
"GuardianGrid"; the app installs as "Octa Resident". Decide which one a
resident should see (noted in the runbook as unfinished).

Residents are app-only — flat number plus the PIN on a printed slip, no
phone number stored — so there is no login_code template and no
hold_at_gate or pass_used. Those are app notifications.

Optional, only if a society asks for resident WhatsApp (not submitted,
switches default false in site_config.json):
   vehicle_movement     "resident_whatsapp": true
   household_decision   "resident_whatsapp": true
